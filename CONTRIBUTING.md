# Contributing to Mirage 3D Scanning System

Thank you for your interest in contributing to the **Mirage 3D Scanning System**.

Mirage is an open-source RGB-D 3D scanning platform based on Raspberry Pi CM5, Intel RealSense D415, and a custom Mirage V1.1 expansion board. The project includes hardware files, software components, documentation, and experimental materials related to RGB-D data acquisition and 3D reconstruction.

## How to contribute

You can contribute in several ways:

* report bugs or setup issues;
* suggest improvements to the hardware or software architecture;
* improve documentation, diagrams, or build instructions;
* share test results, scans, benchmarks, or compatibility notes;
* submit fixes or improvements through pull requests.

## Reporting issues

When opening an issue, please include as much relevant information as possible:

* what you were trying to do;
* what happened;
* what you expected to happen;
* hardware used, especially Raspberry Pi CM version, camera model, and host system;
* software environment, including operating system, compiler, Python version, or relevant dependencies;
* logs, screenshots, or error messages if available.

For hardware-related issues, photos, wiring diagrams, PCB revision information, and power supply details are especially useful.

## Suggesting improvements

Feature requests and design suggestions are welcome. Please describe:

* the problem or limitation you want to solve;
* your proposed change;
* why it would improve the project;
* any compatibility, cost, performance, or complexity trade-offs.

## Pull requests

Before submitting a pull request:

1. Make sure your changes are focused and clearly related to one improvement or fix.
2. Keep code, documentation, and hardware file changes in separate pull requests when possible.
3. Add comments or documentation when the change affects setup, calibration, hardware integration, or reconstruction behavior.
4. Test your changes if practical and describe what you tested in the pull request description.

A good pull request description should include:

* a short summary of the change;
* the reason for the change;
* testing or validation performed;
* screenshots, logs, or photos if relevant.

## Documentation contributions

Documentation improvements are highly appreciated. Useful documentation contributions include:

* clearer setup instructions;
* wiring and assembly notes;
* Raspberry Pi CM5 configuration steps;
* Intel RealSense D415 setup notes;
* reconstruction pipeline explanations;
* troubleshooting sections;
* images, diagrams, or examples.

## Hardware contributions

When contributing hardware-related changes, please include:

* the affected board or module revision;
* schematic or PCB changes;
* design rationale;
* known limitations;
* manufacturing or assembly notes if relevant.

If your change affects compatibility with existing Mirage V1.1 files or components, please clearly mention that.

## Code style

There is no strict formal style guide yet. Please keep contributions readable, consistent with the existing code, and reasonably documented.

For larger changes, prefer clarity over cleverness.

## Community guidelines

Please keep discussions technical, respectful, and constructive. This project is a bachelor thesis prototype and an open-source engineering project, so reproducibility notes, implementation details, and practical feedback are especially valuable.
